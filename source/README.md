# SeatLink · 简洁偏好找座

独立分支 `compact-preferences-ui`。参考组员 V3 推荐规则，在现有 React 模拟器内实现紧凑界面。**本分支没有合并到 main，也没有更改当前 GitHub Pages。**

## 本地运行

```sh
npm ci
npm run dev -- --port 5175
```

打开 http://127.0.0.1:5175/ 。`npm run build` 输出到 `dist/`，资源使用相对路径，兼容 GitHub Pages 的 `/seatlink/`。

GitHub 分支根目录保存可直接静态托管的构建产物；`source/` 保存本项目源文件。克隆该分支后先 `cd source` 再运行以上命令。根目录与 `source/README.md` 分别说明发布结构和开发方式。

## 操作

- 顶部改日期／时间；右侧 **⋯** 展开偏好图标。选中“必须满足”后，不符合或未知都排除。
- 列表／地图切换；“整段”可切换为“含短时”；点击座位查看、备注并预约。
- 底部 **拼座** 进入原时间规划算法；**预约** 查看、取消、续座。
- 右上播放图标打开四个场景：必须换座、先坐再续、有空窗、一张就够。场景使用独立数据，不覆盖普通预约。
- 右上控制图标推进模拟时间或模拟入馆／离馆；“模拟”标记可查看数据说明。

图标带可访问名称与悬停说明，弹层支持 Escape、点击外部关闭和焦点回到入口。手机使用底部详情弹层。颜色之外保留时段、图案、未知问号和状态文字。

## 推荐逻辑与模拟数据

先满足时段，再按偏好匹配数排序；未知不算符合。“必须满足”会同时排除不符合和未知。列表、地图同源，预约提交时重新验证实际时段。

显示屏、HDMI、采光、直晒时段、隔板、通道、空调和附近人数均为**合成演示数据**。完整字段、数量、生成方式和有效期见 [模拟说明](docs/simulated-preferences.md)。没有连接真实预约、视频、门禁或照片数据，也没有接 LLM。

偏好只作用于单座推荐；拼座／续座继续按时间安排，不考虑环境偏好。续座需主动查找或按演示步骤触发，未实现后台监测和推送。

## 预约规则与状态

- 08:00–22:30；22:30 起默认次日，之前默认当天。
- 每段 60–960 分钟，且不能超出当日开馆时间。
- 用户批准的实验规则：可保留多条预约，个人时段不能重叠。
- 入馆即签到，超时 30 分钟释放；离馆释放当天未结束预约。
- 每段默认至少 60 分钟、最多换一次、空窗默认最多 5 分钟；有空窗要单独确认。不额外扣搬东西时间。
- 固定初始时间为 2026-11-19 12:43，不随真实时钟自动推进。
- 83 座中仅 2 个编号位置已核对，其余是临时 SIM 编号。

普通预约继续使用 `c200-reservation-simulator-v2`，演示使用 `c200-guided-demo-v1`，偏好使用独立键 `seatlink-compact-preferences-v3`。每个浏览器各自保存，不是多人服务。

## 验证

```sh
npm test
npm run build
# 先启动开发服务（默认 5175），并安装 Google Chrome：
npm run test:ui
# 也可指定地址和浏览器：
SEATLINK_URL=http://127.0.0.1:5175/ CHROME_PATH=/path/to/chrome npm run test:ui
```

43 项规则／算法测试；浏览器回归覆盖偏好、未知数据、严格提交校验、列表地图一致性、预约备注、刷新恢复、四个演示、完整续座、演示隔离、入离馆、22:30 日期切换，以及 375/390/844 像素布局。截图生成到本地 `.qa/`。

## 文件

- `src/CompactSeatBrowser.jsx` / `compact.css`：简洁界面、偏好弹层、时间列表、预约详情。
- `src/recommendations.js` / `recommendation-service.js`：V3 推荐语义和预约引擎接入。
- `src/seat-profiles.demo.js`：模拟属性，可替换为已核实数据。
- `src/engine.js` / `planner.js`：原预约与拼座算法，见 [算法说明](docs/algorithm.md)。
- `src/scenarios.js` / `DemoControls.jsx`：四个独立演示场景。
- `experiments/`：原只读三种座位可视化草稿，构建为 `public/seat-views.html`，不参与新偏好功能。
