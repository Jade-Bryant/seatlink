# 找座算法接口

本模块计算当前可见的预约安排；不推测未来取消，不调用 LLM，不自动预约。

```js
import { planSeats, planRenewal, bookPlan } from './src/planner.js';

const result = planSeats(state, {
  start: '14:00',
  end: '17:00',
  minSegmentMinutes: 60,
  maxSwitches: 1,       // 第一版支持 0–2
  maxGapMinutes: 5,    // 每个空窗的上限，并非所有空窗总和
  allowPartial: true,
  limit: 3,
});
// date 可省略，22:30 整起自动取次日。数字 start/end 为 Unix 秒。
// 用户确认推荐方案（有空窗时还须确认空窗）后：
const nextState = bookPlan(state, result.plans[0]);

// 从一套已有预约的最后一段之后查续座：
const renewal = planRenewal(nextState, {
  reservationId: nextState.reservations.at(-1).id,
  end: '19:00',
  maxSwitches: 2,       // 包含所选方案中已经安排的换座次数
  minSegmentMinutes: 60,
  maxGapMinutes: 5,
  allowPartial: true,
});
```

主要返回字段：

- `plans[]`：按优先级排列；无结果时 `reason` 说明原因。非法参数抛出可读错误。
- `kind`：`single` 完整且无中断单座；`stitched` 完整分段；`partial` 只覆盖部分。
- `segments[]`：座位、日期、起止 Unix 秒，采用 `[start, end)`。
- `gaps[] / gapSeconds`：明确没有座位的区间及总时长。
- `seatedSeconds`：实际被分配的座位秒数，扣除空窗。
- `unfilledSeconds`：最后一段结束到目标结束之间尚未安排的尾部时长。
- `switches`：新方案的换座次数；同座继续预约不计换座。
- `totalSwitches`：续座结果包含原方案的累计次数。
- `needsRenewal / needsGapConfirmation`：是否还缺尾部、是否需确认空窗。

## 计算方法

先把每张座位已被预约的区间合并，再求开馆时段内的空闲区间，截取用户想学的范围。只使用当前状态，未来释放要等事件真正发生后重新计算。

枚举至多 2 次实际换座的可行空闲区间组合。后一个区间必须比前一个结束得更晚；否则不会提高覆盖，停留原座可得到更少换座的安排。允许间隔后回到同一座位；同座中断续接不占换座次数，但仍受空窗和每段最低时长限制。

对每个组合，从最后一段向前安排切换点，为后面的每段至少保留规定时长，并尽量延长前面的段。例：A 空闲 14:00–16:30，B 空闲 15:00–17:00，最低 60 分钟时，切换点为 16:00，不能贪心坐 A 到 16:30。

完整方案优先；然后依次比较实际有座时长更多、换座更少、第一段更长、空窗更短，最后按座位与时段稳定排序。存在完整方案时不返回部分方案。新找座须在指定开始时刻有座；仅允许换座期间的空窗，不擅自延迟学习开始。续座可以从原段结束后的容许空窗内开始。

## 提交与状态

`bookPlan` 用最新状态再次校验所有分段。内部 `reserveBatch` 不修改输入状态；任何一段与他人或自己现有预约冲突、时间过期或违反规则时，整套失败，不留下部分记录。重复确认同一方案会因个人时间重叠被拒绝。

这是一份浏览器内状态上的整体更新，不是多人服务器数据库事务。接入真实后端时需由服务器实现同样的原子提交与并发校验。

续座不改动原有预约。首次从手动预约续接时，会将原预约与新增预约关联成同一方案，之后能连续追加，并统计总换座次数。被取消、签退或超时释放的原预约不直接续接，需要新找座。

## 验证边界

单元测试涵盖日期门槛、60 分钟下限、重叠、零空窗、5 分钟边界、三段拼接、部分方案、重复确认、失败回滚、释放后续座、累计换座限制。另用 80 组固定随机种子的小规模时间格子，与独立穷举程序对比最优结果。这是算法正确性验证，不是实际图书馆利用率的实验结论。
